UML - QC Component Manager Web v2.0 (Streamlit Architecture)

Tác giả: oke (Chuyên gia QC - Đại Dũng)  |  Ngày: 18/05/2026  |  Phiên bản: 2.0 Web | Tham chiếu: v1.0.2 Tkinter

Mục đích phiên bản 2.0: chuyển từ desktop (Tkinter) sang web app (Streamlit) phục vụ nhiều QC dùng đồng thời qua trình duyệt nội bộ, có authentication, audit log đầy đủ, mobile-friendly, có khả năng mở rộng PostgreSQL khi quy mô tăng.

1. Use Case Diagram (mở rộng cho web)

Phân nhóm Use Case theo màu: Vàng Authentication & Phân quyền — bảo mật web Xanh dương QC Inspector — vận hành hằng ngày Xanh lá QC Manager — quản trị nghiệp vụ Tím nhạt Analytics & Báo cáo — BGĐ & khách hàng Đỏ Admin hệ thống Tím Tính năng nâng cao (mobile, notification, API)

2. Class Diagram (Layered Architecture)

4 lớp kiến trúc: Presentation (Streamlit Pages) → Service (Business Logic - 95% reuse từ Tkinter) → Repository (CRUD trên DB) → Infrastructure (Excel, Cache, Auth, Logger, API). Tách lớp như vậy giúp dễ test, dễ thay DB (SQLite → PostgreSQL), dễ thêm REST API cho Power BI sau này.

3. Sequence Diagram — Luồng Import File Daily DGRP

Key insight: 1 dòng DGRP → tách Remark "Dim,Visual,NDT" → tạo 3 inspection records (DIR, VIR, NDT). Cộng cấu kiện chuyển sang ACCEPTED khi đủ 3 loại đó PASS. Mã được match qua nhiều biến thể (gốc, strip prefix \d+-, strip suffix -J).

4. Deployment Diagram

Triển khai tối thiểu: 1 PC server chạy Streamlit. Client chỉ cần Chrome. Khi nhu cầu tăng (>10 QC đồng thời) chuyển DB sang PostgreSQL. Backup nightly là bắt buộc. Có thể thêm reverse proxy Nginx + HTTPS cert nội bộ.

5. State Diagram — Vòng đời 1 Cấu kiện

Quy tắc chuyển trạng thái: PENDING → IN_PROGRESS khi có inspection đầu tiên · IN_PROGRESS → PASSED khi có PASS cho DIR hoặc VIR hoặc NDT · PASSED → ACCEPTED khi đủ cả 3 (DIR + VIR + NDT) PASS · Bất kỳ trạng thái → FAILED khi có FAIL · FAILED → IN_PROGRESS khi recheck (vd code có -R1 suffix).
